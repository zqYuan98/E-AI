# 电力AI热点：系统功能与集成需求（定稿 v1，2026-10-16）

## 一、定位与边界

- **定位**：面向公司内部的「电力行业 × 人工智能」情报平台。回答三个问题：
  1. 行业里 AI 这几天发生了什么（资讯）；
  2. 国家和两网往哪走、定了哪些目标（政策规划）；
  3. 有哪些研究、数据和观点可以引用（研报）。
- **使用范围**：仅公司内部，需要登录或在内网访问，不对公网开放。洞见研报属于公司付费授权内容，这是硬性要求。
- **不做**：基建招标商机（v2 的定位，已停止）、对外发布、省级单位全覆盖（下一期再做）。

## 三、洞见研报集成

### 3.1 已核实的接口事实（2026-10-16 实测）

- 洞见提供的是**本地 stdio MCP**（安装包 `dongjian-mcp-0.2.0`），共 4 个工具：
  - `dongjian_auth`：网页授权；
  - `dongjian_search`：按关键词、机构、发布日期搜索，每页最多 100 条；
  - `dongjian_content`：读取摘要和正文，长度上限 5 万字；
  - `dongjian_download`：下载 PDF。
- MCP 底层调用的是 **OpenAPI**：
  - 地址：`https://openapi.djyanbao.com/api/`，请求方式 POST；
  - 鉴权：accessKey 加 HMAC-SHA256 签名；
  - 命令：`searchReport`、`getReportContent` 等。
  - 本机实测接口可以访问。
- 凭据的获取方式：在浏览器登录购买会员的账号，确认授权后生成，凭据绑定设备。
- **权限门槛**：洞见页面写明「API/MCP 需**高阶及以上**会员」，并且「**高级版与高阶版是不同套餐**」。另外，创建 Key 本身免费，但调用仍按账号权限和额度执行。

> ⚠ **第一个需要确认的事项**：公司是「高阶会员」，符合洞见公开写明的 API/MCP 门槛，但账号实际权益、调用额度、多人使用和内容许可仍需向洞见确认，或先实际授权试调一次。官方公开资料目前只明确本地 stdio MCP 加本人网页授权，不能据此推定服务器可直接长期调用 OpenAPI。不满足的话，研报库先做成「人工检索后贴链接收录」。

### 3.2 集成方式

平台在服务器端直接调用洞见 OpenAPI，不依赖 MCP 客户端。MCP 是给个人 AI 客户端用的，不适合定时任务和多人共用。具体做法：新建 `modules/research` 模块，按 OpenAPI 的签名规则自行实现调用。

| 环节 | 做法 |
|---|---|
| 凭据 | 管理员在一台电脑上用洞见官方工具完成一次授权，把 accessKey / accessSecret 写进服务器 `.env`（`DONGJIAN_ACCESS_KEY` / `DONGJIAN_ACCESS_SECRET`），不进代码仓库。凭据失效时后台告警，需要重新授权 |
| 定时检索 | 每天按主题词表搜索近 7 天的研报，例如：电力 人工智能、电力大模型、智能电网、虚拟电厂、算电协同、新型电力系统、国家电网、南方电网。只存元数据：标题、机构、日期、报告 ID、洞见链接、摘要 |
| 重点精读 | 模型按相关度挑出少量重点报告，调用 `getReportContent` 读正文，抽取关键数据、预测和观点，每条附原话。和政策规划库的核对规则一样，原话找不到就不保存 |
| 关联 | 研报关联到政策规划库的文件、两网全景页和主题页 |
| 站内检索 | 内部用户在站内搜索研报：由服务器代为调用，限次数，结果缓存 |
| PDF | 平台**不存储、不转发** PDF。阅读原文时跳转洞见网站，由用户用公司账号自行查看 |
| 计费与熔断 | 每次调用都走框架的付费请求回执，重启或重试不重复计费；每分钟、每天设调用上限，超限自动暂停 |

### 3.3 需要洞见方面明确的问题

1. 公司现有套餐是否包含 API 权限？不含的话，升级到高阶的费用是多少？
2. 调用额度：每天、每月的搜索次数和正文读取次数，并发和频率限制。
3. 设备凭据能否部署在服务器上长期使用？有效期多久？是否允许多台设备？
4. 使用条款：
   - 是否允许在公司内部平台展示摘要和摘录；
   - 是否允许做模型抽取后的二次整理；
   - 对内部共享的人数或范围有无限制。
5. 有没有按行业或主题订阅、增量推送的接口。如果有，就可以替代定时搜索。

## 五、非功能要求

- **可追溯**：所有模型产出（摘要、目标指标、AI 条款、研报观点）都附原文出处或原话；原话核对不上的内容不展示。
- **成本可控**：每个付费服务（模型、洞见、公众号）都有回执和分钟、小时、天三级上限；后台能看到调用量和费用。
- **版权**：信源默认只展示摘要和原文链接；研报不转发 PDF、不展示全文。
- **可维护**：行业配置（分类、信源、提示词、门槛）都在 `industry/`，自有功能放在 `modules/`，能持续合并 AIHOT 上游的更新。
- **测试**：每次上线前跑类型检查和全量测试。目前 678 个测试里，只有 Windows 环境跑不了的 3 个文件失败，在服务器上会通过。

## 六、实施顺序

1. **恢复运行**（等 I1）：配置并切换到可用的模型服务商，重新导入政策种子，观察自动抽取效果 1 到 2 天。
2. **洞见确认**（第三节第一个确认事项，以及 3.3 的 5 个问题）：确认权限后开发 F6 研报库，约 1 周。
3. **门槛校准**：标注 150 到 200 条资讯，用 SelectBench 定门槛。
4. **F5 两网全景**，以及 F7 统一检索。
5. **部署 37 服务器**（I4），配置飞书推送（I3）。
6. 视情况启用公众号（I5）、接入知网（I6）、扩展省级单位。
