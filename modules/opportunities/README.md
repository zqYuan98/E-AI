# 项目商机（modules/opportunities）

商务组做“盲投”：没有前期客户跟进，靠公开招采信息找与公司业务对得上的项目。国网的采购公告在列表上只有批次名（“××公司2026年第五次服务授权竞争性谈判采购”），真正采购什么写在公告文件里的需求一览表。这个模块把它自动做完：

1. **发现**：每 20 分钟看一次国网电子商务平台（ECP）和电工交易专区的“采购公告”“招标公告”列表最前面 20 条，新的入库。
2. **取附件**：每 5 分钟取几份新公告的公告文件（“下载公告文件”），解析其中的 Excel（XLSX、旧版 XLS、嵌套压缩包），拆成具体项目：分标、包、子包、项目名称、采购内容、最高限价（万元 / 元 / 折扣率分开）、资质、业绩、人员要求，以及原文位置。不用 OCR，也不点“获取采购文件”（要登录、购买的那部分不碰）。
3. **筛选**：按后台“项目商机”里的**业务口径**：项目名称命中排除词的直接无关；其余每 60 个一批交给模型，判断相关 / 待确认 / 无关并写一句理由。模型没开、出错或预算用完时不卡住：命中方向关键词的记“待确认（关键词命中）”，其余无关。相同的项目文字会复用已有的模型结果，不重复花钱。
4. **推送**：一份公告里有相关或待确认的项目就推一条到钉钉群（自定义机器人，加签），写明项目、包、限价、业绩与资质要求、采购文件获取截止、开标时间和链接；每天 8:30 再推一次汇总（过去 24 小时新发现的数量、3 天内采购文件获取截止的项目）。每条消息只推一次：明确失败的最多再试两次，结果不明的不重发。第一次采集时列表上已有的存量只入库不推送；采购文件获取已截止的、取到附件已超过 48 小时的也不实时推。
5. **查看**：`/opportunities` 按项目列出（默认相关和待确认），点开是整个批次：对得上的项目全部字段和原文位置，其余项目的名称和包。手机底栏的“商机”指向这里；南网等其他招标仍在“招标商机”频道。

时间、批次、采购人、限价都照抄来源原文；“采购文件获取截止”“开标（开启应答文件）时间”不是投标截止时间，页面和推送都这样写。

## 采集服务（fetcher/）

国网门户有动态反爬：每次接口请求都带页面脚本生成的参数。所以不直接调接口，而是用真实浏览器（Playwright + Debian 的 Chromium）像人一样打开列表和公告、点“下载公告文件”（会弹出新窗口下载）。这部分在同一 compose 里的内部容器 `sgcc-fetcher` 里跑，worker 通过 `OPPORTUNITIES_FETCHER_URL` 带令牌调用，不对外开放端口。说明见 `fetcher/README.md`。

## 配置

- `.env`：`OPPORTUNITIES_FETCHER_URL`（内网部署为 `http://sgcc-fetcher:8000`）、`OPPORTUNITIES_FETCHER_TOKEN`（至少 24 位，compose 用它启动采集服务）。两项都填才采集；采集还受 `COLLECT_ENABLED` 和后台“运行开关”控制。
- 推送：`DINGTALK_ROBOT_WEBHOOK`、`DINGTALK_ROBOT_SECRET`，安全阀 `DINGTALK_PUSH_ENABLED=true` 才发。
- 模型：后台“模型与评测”里的“项目商机筛选”一步（`OPPORTUNITIES_MODEL`）；模型调用受 `MODEL_CALLS_ENABLED` 和运行开关控制。
- 业务口径：后台“商机 → 项目商机”，每行“方向名：词、词、词”，另有排除词；保存要写原因，记审计。改了口径只影响之后筛选的公告。

## 数据

`opp_notices`（公告）、`opp_items`（项目）、`opp_pushes`（推送记录）。无关和没筛的项目保留 90 天，相关和待确认的一直保留。附件原文件不保存，需要时到原公告下载。
