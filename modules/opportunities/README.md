# 投标商机（modules/opportunities）

商务组做“盲投”：没有前期客户跟进，靠公开招采信息找与公司业务对得上的项目。每条商机都要看得出**采购什么、限价或预算、资质 / 业绩 / 人员要求、和我司资质对不对得上、截止时间**。来源有两类：

- **国网**（电子商务平台 ECP、电工交易专区）：公告在列表上只有批次名（“××公司2026年第五次服务授权竞争性谈判采购”），真正采购什么写在公告文件里的需求一览表，要下载附件拆开。
- **其他招采平台**：信源里打了“招标”“招标计划”标签的资料（南网、三峡、电建、公共资源交易……），一条资料当一份公告、一个项目，按信源名“平台·栏目”里的平台分开（南方电网供应链、三峡集团电子采购平台、中国电建阳光采购网……），列表的来源筛选和推送群都按平台选。打了“中标”标签的信源，以及标题是中标、成交、候选人公示、更正、终止这类的不收，只看还能投的。原来的“招标商机”频道并进了这里，旧地址 `/tenders` 跳转到 `/opportunities`。

流程：

1. **发现**：每 20 分钟看一次国网两个平台“采购公告”“招标公告”列表最前面 20 条，新的入库。其他平台的资料每 5 分钟从已采集的资料里登记最近 7 天的（正文还在抓的等两小时，没等到就用摘要）。
2. **取附件**（国网）：每 5 分钟取几份新公告的公告文件（“下载公告文件”），解析其中的 Excel（XLSX、旧版 XLS、嵌套压缩包），拆成具体项目：分标、包、子包、项目名称、采购内容、最高限价（万元 / 元 / 折扣率分开）、资质、业绩、人员要求，以及原文位置。物资招标的货物清单一行一种物资（一份几千行），按分标+包合成一条，名称用物资类别，采购内容列出物资名称。附件里的 Word 公告正文也留下（最多 3 万字），下一步抽要素用。不用 OCR，也不点“获取采购文件”（要登录、购买的那部分不碰）。
3. **筛选**：按后台“投标商机”里的**业务口径**：命中排除词的直接无关；其余每 60 个一批交给模型，判断相关 / 待确认 / 无关并写一句理由（其他平台的资料攒成一批，不逐条调用）。模型出错时先等，取到附件 6 小时后还不行就按关键词兜底：项目名命中方向关键词的记“待确认（关键词命中）”，其余无关。相同的项目文字会复用已有的模型结果，不重复花钱。
4. **抽要素**：有相关或待确认项目的公告，把公告正文交给模型抽预算、获取 / 报名 / 投标截止和开标时间、联合体、资质 / 业绩 / 人员等通用要求和标包，每项带原话；程序逐条核对原话在正文里（时间核对月日、金额核对数字），对不上的去掉。提示词沿用招采公告抽取（`industry/prompts/tender-extract.md`），格式在 `backend/details-schema.ts`。来源没写的获取截止、开标时间和采购人用抽出来的补上。
5. **资质要求与匹配度**：每个相关或待确认项目的资质、业绩、人员要求 = 项目自己表格里写的（资质和业绩写在同一列的，按“业绩要求：”小标题拆开）+ 公告正文里适用于它所在包的通用要求（`backend/requirements.ts`）。集团下有多家公司可以投标，**我司资质按公司分开**：资质证书从宜搭“资质/荣誉台账”同步（`backend/yida.ts`，只读，每天 07:30，后台可试读、手动同步；整表替换，有效期已过的不算），人员证书、业绩和其他后台手填，每行“公司：内容”（`backend/company.ts`）。要素抽完后把要求和各公司的条件交给模型，对每条要求说出哪些公司满足、哪些不满足，其余需核实（提示词 `industry/prompts/opportunity-match.md`，一份公告一次调用，项目多时每 20 个一批）；一家公司只看它自己的条件，不跨公司拼。程序按“不满足少、满足多”挑出**建议投标主体**，匹配度按它算：有不满足为低，有需核实为中，都满足为高。条件变了（同步到新资质、资质过期、手填改了）以后，还没截止的项目重新比；什么条件都没有就不比。模型漏答的项目不记，公告记一次失败，3 次后不再自动试。
6. **推送**：每天 **08:30、17:30** 给后台配的每个**推送群**（每个钉钉群一个自定义机器人，加签，可以有多个）推一期**盲投信息表**：列出这个群还没收到过的项目，按截止时间排序，每个项目同样几项要素——名称（点开是详情）、采购人、地区、限价或预算、获取 / 投标截止、资质 / 业绩 / 人员要求（没写的写“未写明”或“详见招标文件”）、匹配度（含建议投标主体）和来源。消息里最多列 10 个，全部项目在站内这一期的信息表页（`/opportunities?sheet=<key>`，表格，可导出 Excel）；末尾再提醒之前推过、48 小时内截止的项目，@ 关注这些方向的提醒人（没写方向的有新项目就 @）。钉钉机器人的 markdown 在手机上不显示表格，所以消息里是固定顺序的要素清单。每个群自己选推哪些业务方向和平台、要不要待确认（其他平台的待确认一律不推）。只列要素抽完（填了我司资质的还要比对完；模型不行时最多等到取到附件 6 小时）、没截止、最近 7 天、群加上（或重新启用）以后发现的公告；第一次采集时已有的存量只入库不推送。一期明确失败的随每 5 分钟的处理在本期内最多再试两次，没推成的项目留到下一期；结果不明的不重发，那些公告算这个群收到过。
7. **查看**：`/opportunities` 按项目列出（默认相关和待确认），可按来源平台、业务方向和搜索词筛选，卡片或表格两种看法，按当前筛选导出 Excel（CSV，最多 2000 个）；卡片和表格上都有资质、业绩、人员三行和匹配度，不显示筛选理由。点开是整份公告：公告要素（各包都适用的预算、时间和通用要求，可展开看原文）、对得上的项目全部字段、逐条要求和对比说明、原文位置、其余项目的名称和包。侧栏“频道”里的“投标商机”和手机底栏的“商机”指向这里。

时间、批次、采购人、限价都照抄来源原文；“采购文件获取截止”“开标时间”不是投标截止时间，投标截止单独写。

## 采集服务（fetcher/）

国网门户有动态反爬：每次接口请求都带页面脚本生成的参数。所以不直接调接口，而是用真实浏览器（Playwright + Debian 的 Chromium）像人一样打开列表和公告、点“下载公告文件”（会弹出新窗口下载）。这部分在同一 compose 里的内部容器 `sgcc-fetcher` 里跑，worker 通过 `OPPORTUNITIES_FETCHER_URL` 带令牌调用，不对外开放端口。说明见 `fetcher/README.md`。没配采集服务时，其他平台的资料照常筛选和推送。

## 配置

- `.env`：`OPPORTUNITIES_FETCHER_URL`（内网部署为 `http://sgcc-fetcher:8000`）、`OPPORTUNITIES_FETCHER_TOKEN`（至少 24 位，compose 用它启动采集服务）。两项都填才采集国网；采集还受 `COLLECT_ENABLED` 和后台“运行开关”控制。
- 推送：安全阀 `DINGTALK_PUSH_ENABLED=true` 才发；推送群在后台“商机 → 投标商机 → 推送群”里加、改、停用、测试（改动写原因，记审计）。Webhook 和加签密钥存在库里，后台只显示 Webhook 末尾几位，审计里不记。
- 模型：后台“模型与评测”里的“投标商机”一步（`OPPORTUNITIES_MODEL`），筛选、抽要素和比对资质都用它；模型调用受 `MODEL_CALLS_ENABLED` 和运行开关控制。
- 业务口径：后台“商机 → 投标商机”，每行“方向名：词、词、词”，另有排除词；保存要写原因，记审计。改了口径只影响之后筛选的公告。
- 我司资质：资质证书在宜搭“资质/荣誉台账”里维护，`.env` 填 `YIDA_APP_TYPE`、`YIDA_SYSTEM_TOKEN`、`YIDA_USER_ID`、`YIDA_QUALIFICATION_FORM`（加上已有的 `DINGTALK_APP_KEY` / `DINGTALK_APP_SECRET`，应用要开通“宜搭表单数据读权限”）。字段按标题认（类型、资质/荣誉名称、所属公司、有效期），取不到标题时按取值认；后台先“试读”确认字段，再“立即同步”，同步写原因、记审计。人员证书、业绩和其他在后台“商机 → 投标商机 → 我司资质”手填，存在 settings 的 `opportunities.company`，保存要写原因，记审计。

## 数据

`opp_notices`（公告，含公告正文 `doc_text`、抽出的要素 `details`、比对失败次数 `match_failures`）、`opp_items`（项目，`match` 是按公司的逐条比对结果，`match_key` 是比对时各公司条件的指纹）、`opp_company_quals`（从宜搭同步的资质，每次同步整表替换；最近一次同步的结果在 settings 的 `opportunities.yida_sync`）、`opp_push_groups`（推送群）、`opp_pushes`（推送记录：每期信息表 `g<群>:sheet:<日期>:am|pm` 一行，`items` 记它列的项目；群收到过的公告 `g<群>:notice:<公告>` 一行；删群时一起删）。无关和没筛的项目保留 90 天，相关和待确认的一直保留。附件原文件不保存，需要时到原公告下载。
