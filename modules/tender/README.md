# 招采申报（modules/tender）

把“招采申报”类资料（`industry/taxonomy.ts` 的 `procurement`：招标采购、中标结果、项目前期、申报通知）里的关键要素认出来，
给投标、售前和申报的同事一个按截止时间排好的列表 `/procurement`，并在条目页标题下显示“标讯要素”。

- **认什么**：公告阶段（招标采购、变更澄清、候选人公示、中标结果、终止流标、招标计划、项目前期、申报通知）、投标（响应、报价）截止、
  报名或获取文件截止、金额（预算、最高限价、估算价；结果公告里是中标或成交金额）、采购人、代理机构、中标人或第一候选人、项目编号、地区。
- **怎么认**：`backend/extract.ts`，纯规则，不调模型、不联网。字段词表借鉴开源项目
  [招投标大师](https://github.com/Lappercn/tender-master)（MIT）的 `crawl/extract.py`，按本站采集到的真实正文重写：
  只认带标签、紧挨着值的写法，认不准就不给；每项带原文那一小段，页面上可以展开核对。
- **什么时候认**：worker 每 2 分钟认一批新发布或正文改过的资料，结果存在 `tender_facts`（资料删了跟着删）。
  改了规则就把 `EXTRACTOR_VERSION` 加一，已有的会在之后几轮里重新认。
- **列表怎么排**：可投标、申报通知按截止时间由近到远，已截止的默认收起（页面底部可以展开）；没认出截止时间的招标公告，
  发布三周内仍算可投标；中标结果、项目前期按发布时间新的在前。只看近 90 天。地区筛选把本站重点省份（皖甘宁滇）排在最前，可以一起选中。
- **不做**：不抓联系人姓名和电话（个人信息，要用请看原公告）；不下载、不转存招标文件和附件（以平台上的最新版为准，旧附件会导致废标）；
  不用浏览器自动化或反检测手段采集任何平台（信源仍按 `industry/sources.json` 的公开列表和接口采集）。

## 改规则

先在 `tests/extract.standalone.test.ts` 加一条真实写法（去掉联系人和电话），再改 `backend/extract.ts`，`npm run test:standalone` 通过后把
`EXTRACTOR_VERSION` 加一。重点省份在 `types.ts` 的 `FOCUS_REGIONS`。
