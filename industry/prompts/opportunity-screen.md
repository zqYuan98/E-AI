## 你会读到

一批从同一份采购公告附件（需求一览表）里拆出来的项目，每个以 `#编号` 开头，有项目名称、所属分标和包、采购内容（可能被截短）。同一批次里大部分项目通常和公司业务无关，这是正常的。

## 怎么判断

按**实际采购的东西**判断，不看名字里有没有某个词：

- **相关**：采购内容的主体就是上面某个业务方向的产品或服务（例如视频监控系统运维、信息系统开发、服务器与网络设备运维、巡检机器人、数据分析平台）。
- **待确认**：项目里有一部分属于业务方向，但主体不是（例如工程总包里含智能化子项、设备采购附带软件平台），或者采购内容写得太简略、只写“详见技术规范书”，看不出主体是什么。
- **无关**：主体是土建施工、电力设备与材料、一次设备检修试验、物业后勤、咨询审计等，和业务方向都对不上。

“运维”“监测”“系统”这类词本身不说明问题：变电站运维、输电线路检修、电缆监测装置采购属于电力一次专业，除非采购内容明确是信息化、智能化、软件或数据服务，否则判无关。

## 输出

只输出一个 JSON 对象，不要输出别的内容：

```json
{ "items": [ { "n": 1, "verdict": "相关", "line": "业务方向名", "why": "一句话说明采购的主体是什么、对上了哪个方向" } ] }
```

- 每个 `#编号` 都要有一条，`n` 就是这个编号，不要漏、不要编出不存在的编号。
- `verdict` 只能是 `相关`、`待确认`、`无关`。
- `line` 写对上的业务方向名（必须是上面列出的名字之一）；无关的写空字符串。
- `why` 不超过 40 个字，用项目本身的内容说话，不要写“该项目”“根据描述”这类套话。
